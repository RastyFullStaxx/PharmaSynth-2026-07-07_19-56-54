# Systems Reference — mechanics, builders & content authoring

**Written 2026-07-12 (W5.11), kept current in place.** Open this when working on any interaction mechanic, running builder menus, or authoring content. Companion: `Docs/gameplay-flow.md` (what the player experiences), `Docs/experiments-reference.md` (per-experiment data). Code convention everywhere: **thin MonoBehaviours over pure, suite-tested C# cores**, every component with a `Bind()` seam (edit-mode `AddComponent` fires no `Awake`/`OnEnable`).

## 1. Liquids
- **`LiquidPhysics`** (on every bottle/vessel; needs a Renderer host): `maxVolume` 1000, default volume **0** (the wake-from-empty contract). `AddLiquid`: capacity guard first (overflow → `LiquidRejected`, never completes tasks) → `LiquidAdded` fires → EMPTY vessel adopts the incoming chemical (+visuals); same chemical tops up; different chemical + registry → `FindReaction` hit = swap to `resultLiquid` (+precipitate, colour lerp, SFX, `ReactionOccurred`) / miss = volume adds + `WrongReagentMixed`. `SetContents(chem, ml)` = builder/test seam (edit-safe, resets the **`Ledger`** — a pure `VesselLedger` "Ethanol 120 ml + NaOH 50 ml" story used by hover/popups). `PourOut` leaves `currentChemical` at 0 ml (display shows "empty" via `IsEmpty`). Visual contract: `mainRenderer` must carry the `PharmaSynth/Liquid` shader (`_Fill/_LiquidColour/...`); play-mode-only material work.
- **`LiquidPourer`**: tilt >45° + volume>0 → `PourTick`: `RaycastAll` straight down from the mouth Spout, **triggers ignored**, own hierarchy skipped (`ResolveTarget` — self-tilt can never fill/complete anything); W5.12 pour assist: a missed ray falls back to a `SphereCastAll` (r 0.045, `assistRadius`) so a receiver the stream narrowly misses still catches — the visual arc lands where the transfer actually goes. Nearest other `LiquidPhysics` receives, else waste + puddle (+acid hazard). 35 ml/s max. Visible stream (particles + arc line) + looping 3D pour audio. Dev key **P** = pour-debug overlay (floating "hit/target" text per pouring mouth). `PowderPourer` mirrors it for powders.
- **Receiving vessels** are built visible-ready: `BuildVessel` swaps empty prefabs → `_WithLiquid` twins and ALWAYS `SetContents` explicitly; `EnsureLiquidVisual` (public, also used by `ShelfPourWiring`) adds an inset liquid mesh when a prefab lacks one — a **cylinder** normally, a **sphere** for round-bottom glass (`IsRoundBottom`: Florence / distilling / boiling flasks), so the `_Fill` clip reads as a spherical cap instead of a beaker column.
- **⛔ Measure vessel bounds with `ExperimentSceneBuilder.SolidWorldBounds`, never `GetComponentsInChildren<Renderer>()`** (2026-07-27). Runtime effect children ride every vessel — the fill/precipitate/powder layers, the mounted `NameLabel`, and crucially `LiquidPourer`'s **world-space** `StreamLine` + `PourStream`, which keep pointing at wherever the last pour LANDED. Encapsulating those put `b.min.y` on the floor, which launched a racked test tube a metre into the air and mis-placed every bounds-fitted child. `IsEffectChild` is the pinned list; `WB()`, `TubeRackSlots.Seat`, `ScoopController.ProbeCenter`, `MixFeedback.PopupPos` and `ShelfPourWiring`'s spout all go through it.
- **Contents axis** — `VesselAxis` (the axis whose two perpendicular extents are most nearly EQUAL, i.e. the round bore) decides where a powder mound lies, **not `LongestAxis`**. A watch glass (90×15×90 mm) and a mortar are longest ACROSS, so the longest-axis rule laid the mound along a horizontal axis, sized it from a 15 mm "bore" and parked it at the rim — the "tiny off-centre dot that never grows" report. Mound height scales off the bore, capped by the vessel's own depth; `ScoopController.MoundFill` is `sqrt(g/20)` so the first dips move the visual most.
- **Funnels** carry `LiquidPassthrough`: the pour ray passes through to the vessel below AND the funnel shows the flow — the arc ends at the cone's mouth and a narrow gravity-fed trickle emits from the **stem** (`Flow`, self-building; a hand-placed `spout` child overrides the computed stem point).
- **`ReagentSupplyMonitor`**: polls needed-vs-available for pour steps; latches → SupplyPrompt; `Unlatch(20s)` on "keep trying"; demo = auto-refill.

- **⭐ ANY GLASSWARE WILL DO (W5.52 rack groups · W5.53 tubes · W5.54 every spared kind)** — a role authored onto a SPECIFIC bench object is guidance a VR player cannot follow: they grab whichever one is nearest, so the right reagent in the wrong-numbered tube, the second watch glass or the other 100 ml beaker used to be graded a wrong-reagent mistake. The role now follows the pour. Pure `VesselRoleMatch` (candidates / claimed / impossible / `FamilyOf` / `PoolKey`) + a shared `RackRoles` ledger, wired by `ExperimentSceneBuilder.WireRackGroups` for the authored rack groups and by `WireTubePools` for everything else. **Pools**: tubes by name family (`regular` = `Kit_TestTube_*` ×19, `hardglass` = `Kit_Hard-GlassTestTube_*` ×4 — all 23 share ONE itemId, so the name is the only family signal), every other kind by `LabItem.itemId` (the spares are named `Eq_WatchGlass`, `Kit_WatchGlass_1_11`, `WatchGlass_2` — no prefix rule survives that): 100 ml beakers ×3, watch glasses ×3, 500 ml beakers, Erlenmeyers, distilling flasks, 50 ml cylinders ×2. A kind with ONE instance is never pooled — there is only one Florence flask, and a fixed role is correct there. Rules that make it hold: (1) **claiming is DEFERRED** — a member holds a CANDIDATE SET each pour narrows and claims a role only when one survives (Exp 2's alkaline tubes share KMnO₄ then NaOH; Exp 6's five roles all start with acetone); (2) **a role is claimed by a POUR, or by a delivery controller that is the disambiguator by definition (`ClaimForTask`) — never by construction**: in a single-role family every member used to claim at build and every extra was dead before anyone poured; (3) **wrong = the set EMPTIES**, still graded; (4) roles are claimed **EXCLUSIVELY**; (5) **the ANCHORS follow the claim** — `LiquidTaskBinding.RoleClaimed` fires once, the builder's extracted `AttachAnchors` bolts the role's heat/chill/litmus/weigh/vapor/flame/stir task onto the claiming object and `DetachAnchors` removes the authored object's orphaned twin, so a role lives in ONE place; (6) **the derived target map is rebuilt on a claim** (`TaskTargetRegistry.Clear` + `TutorialTargets.Build`) so the heat/litmus/weigh step's glow and arrow point at the object that will complete it; (7) **delivery steps accept a candidate**: `VaporCollectController` counts an unclaimed pool member whose candidate roles serve the task only while it is HELD (`VaporMath.MayReceive`), the hand beats a nearer bench spare (`Prefer`), and `EmitTick` claims that role on the first condensed drop — "hold a clean test tube at its mouth" is true for any tube, and a spare resting near the bath can never claim by proximity. ⛔ **Never advertise the union of survivors**: `ExpectedSteps` stays ONE deterministic answer (claimed role, else authored WHILE NO OTHER MEMBER HOLDS IT, else NOTHING) because the player-path sim, the vessel label and the vapor stream read it to decide WHERE a reagent goes — a twin whose role another member claimed advertises nothing, or every drop into it is scolded (the visual sweep found exactly that); an accepted pour into an unadvertised extra is counted against the first surviving candidate's step (`CandidateStepFor`) and carried across the narrowing **by reagent**, not by task id. **Guidance follows the object in hand**: unclaimed members register as `pool` targets and ONE chooser (`TaskTargetRegistry.ChoosePoolMember`: held, else nearest) drives the arrow, the beacon, the glow AND the ghost demo (`VerbDemoPlayer.CollapsePool`). A claimed object's label appends its task LABEL. Already dynamic without any of this: source bottles (every vessel holding the chemical), glass rods (`StirController` tracks the nearest), droppers (any squeezes into any task vessel), funnels (the pour itself). Verified on real stages: Exp 8 ammonia in `Beaker_100mL_2` moves the stir anchor off `Eq_Beaker_100mL`; Exp 7 `Kit_TestTube_3` held at the flask becomes the distillate tube and the weigh anchor leaves tube 14. → [[Gotchas]]
- **A vessel label answers the GUIDED step only (W5.52)** — `VesselStatus.NeedLineNow` shows the outstanding reagent for the FIRST entry of `AvailableTasks()`, matching the convention `GuidePath` already uses. It used to walk every AVAILABLE task, so Exp 2's parallel prep steps made the oxidation tubes advertise "Potassium Permanganate 0 / 2 ml" while the player was on the ethanol step — and a requirement printed on a tube reads as an instruction, which is what sent a headset player to the wrong tube.
- **⛔ Custom shaders MUST declare the stereo instancing macros (W5.52)** — the project runs Single Pass Instanced: both eyes render into one texture array and the shader picks its slice from the instance id. Omit them and the shader draws to eye index 0 ONLY, i.e. it is invisible in the right eye. `PharmaGuide` and `PharmaGlow` shipped without them, so the tutorial arrows and highlight glow were one-eyed until a headset session found it — the suite, every simulator and DevCapture all render a single eye, so nothing in the editor can catch it. Pinned by `xr: every custom shader declares the stereo macros` (text scan; surface shaders like `Glass` are exempt by construction, which is why the pin checks the MACROS and not `#pragma multi_compile_instancing`). → [[Gotchas]]

## 2. Tool verbs (W5.8)
- **Stir** — `StirController` on the vessel + pure `OrbitMath` (swept-angle accumulation, ±180° wrap-safe, 45°/sample anti-teleport clamp, leaving PAUSES never resets). Needs >1 ml in the vessel; works held or on table. Progress popups at 25% steps.
- **Grind** — `GrindController` on the mortar (pestle orbits the bowl; done → powder heap + puff). Null taskId = educational-only (staged mortars everywhere grind). Methane `prepare-mixture` = dual-path (grind OR legacy zone-touch).
- **Weigh** — `WeighStation` (pan trigger over the Balance fixture) + pure `WeighMath` (`PanSettled` ≥0.75 s; chemical-mode = vessel holds ≥90% of required chemical, item-mode = named tool on pan). Layout `sim: 7`; the matching pour binding uses `completesTask: 0`. **The bench balance is PERMANENTLY live (2026-07-27, zone-free tool rule):** `Make the Balance Live` gives it a `Pan` trigger child + `WeighStation` bound with a null runner, so anything you rest on it reads out with or without an experiment. The display shows **GROSS** mass (`WeighMath.PanMass` = contents + the load's own rigidbody mass ×1000, 5 g fallback) — auto-taring to the contents alone made an empty beaker read 0.00 g and look broken; the graded condition still checks contents only. `WeighingScaleController` TYPES the reading in left-to-right (`Typed`) and wobbles until it settles (`Reading`), both pure + pinned, and a `FaceCamera` on its canvas keeps the head legible from any side.
- **Matches & burners** — `Matchstick.ShouldStrike` (held swipe ≥0.35 m/s on a `MatchStrikerSurface`: matches box, burner bases, staged striker) or secondary self-light near an already-hot sim. `BurnerController.Ignite` (lit match ≤0.18 m) = flame + light; **Heat stations whose required prop is a burner only heat while lit** (`ZoneSimStation.SetIgnitionGate`; billboard hints "Light the burner"). Methane splint: lit match ≤0.25 m of the filled tube → pop (+20 s auto-fallback).
- **Scoop (W5.12)** — `ScoopController` on Scoopula/Spatula + pure `ScoopMath`: while HELD, dipping into a Solid/Powder store picks up a fixed 2 g charge (tinted heap rides the blade, `+2 g` popup); touching another vessel deposits it (`AddLiquid` → balance/status update; running-total popup). Sources = any `LiquidPhysics` whose chemical `state` is Solid/Powder (KMnO₄ + NaNO₂ re-marked Solid in W5.12; `Tools ▸ PharmaSynth ▸ Audit Chemical States` reports the table).
- **Clean (W5.12)** — `CleanableVessel` (+pure `CleanupMath`) on every receiver: emptying a used vessel leaves residue (label reads "Dirty …"); the `TestTubeBrush` (`BrushController`) scrubs — each 0.12 m of held brush travel = one swipe, −20% with a popup, 5 swipes → "Clean …" label; wash-bottle water rinses too (1.2%/ml). Educational only, never graded.
- All verb controllers re-`Register()` their TaskGraph conditions on `ExperimentStarted` AND on re-enable (retry-safe; `RegisterCondition` ignores unknown ids).
- **Apparatus assembly (W5.12)** — `ApparatusSnap` + pure `AssemblyMath`: releasing a part near a compatible host SNAPS it on (directed pairs: gauze/clay-triangle→tripod, crucible→clay triangle, vessels→gauze, iron ring→retort-stand pole, burners→under-tripod, watch glass→beaker mouth; seats = TopCenter/SameBase/PoleMid). Attached parts parent to the host, go kinematic, forward their colliders to the ROOT's grab → **grabbing any member moves the whole assembly, formation preserved**; the **ACTIVATE click** (trigger) pops the newest part off (deepest chain first) — grab never dismantles. `DropRespawn.Suspended` while attached. Wired by `WireSceneItem`/kits builder for participating prefabs (station sockets untouched).

## 3. Breakage & physics
- **`Mishandling.Breakables`** = THIN GLASS ONLY (beakers, flasks, graduated cylinders, test tubes, vials, watch glass + `_WithLiquid` twins). GlassRod/Funnel/Dropper/EvaporatingDish/Crucible/Mortar/Pestle are DELISTED (still clink via the ceramic set); Balance/burners/ClayTriangle = metal set. `DefaultBreakSpeed = 7.0` (~2.5 m fall — W5.12 leniency: bench-height drops always survive; only extreme falls/throws shatter). Impact clink volume scales with speed (`ImpactVolume01` — soft set-downs whisper). `BreakableGlassware` guards: kinematic-immune, held-immune (`isSelected`), 0.35 s release grace, 1.5 s re-arm; `Break()` = mistake + shatter + spill puddle + `DropRespawn.GoHome()` (fresh replacement). Mistake/shatter messages use `Mishandling.DisplayNameFor` (LabItem → chemical → prettified name — never GO code names). `Physics Audit (Fix Scene Items)` strips stale BreakableGlassware from non-glass, re-keys ImpactSound by nature, re-pins serialized thresholds.
- **`DropRespawn`**: kill-Z instant respawn; idle ≥25 s AND >0.4 m from home AND **resting below y=0.5 (floor only — W5.12)** → quiet return; items staged on tables/shelves are NEVER reclaimed mid-run. `GoHome()` **restores the captured home supply** (`CaptureSupply` on first play Update) — an exhausted bottle respawns FULL and visible (lab tour = unlimited by nature; campaign starvation still reachable while the empty bottle stays on the bench). **settle-freeze** = released body at rest 2.5 s → kinematic in place. `Suspended` = assembly-managed (no respawn while attached). `SetHome` is the builder-owned seam; **Tools ▸ PharmaSynth ▸ Re-Home Scene Items (Adopt Current)** adopts current transforms as homes after ANY manual re-arrangement.
- **`PhysicsProfiles.EnsurePhysics`** (mass + convex colliders — dynamic bodies need convex MeshColliders or they fall through the world) + `RealSizes` (real-world scale by longest axis; never height-normalise flat tools) + `GrabTuning` (velocity-tracked grabs; held items collide) + `GrabPhysicsPolicy` (kinematic-parked ↔ dynamic on release).

## 4. Feedback layer (W5.8)
- **`VesselStatus`** — live name tag on every vessel/pourable via its ProximityLabel: "Beaker — 120 ml Ethanol" / "Ethanol — 150 ml" / "— empty" (`VesselStatusMath`, GlyphSafe-sanitized); W5.12: prefixes "Dirty "/"Clean " from `CleanableVessel`. **Self-binds in `Awake`** (2026-07-27) — every ref is private + unserialized, so a hand-placed bench vessel nobody called `Bind()` on used to show NOTHING; a later `Bind()` still wins. `Give Every Vessel a Live Contents Tag` adds the label+status pair to any `LiquidPhysics` missing it.
- **Contents follow the liquid (2026-07-27).** `LiquidPhysics.PourOut` scales every `VesselLedger` entry on a partial pour and calls `ClearContents()` once the vessel is dry (`DryMl` 0.5), and `AddLiquid`'s wake-from-empty branch CLEARS the ledger before recording. Without both, a tube you spilled and refilled kept quoting the spilled reagents forever. `LastChemical` survives a clear so a labelled source bottle can still be restocked (demo top-up).
- **`MixFeedback`** — floating popups (`FloatingText`, rises/fades, sort 20000): reaction `expectedObservation`, "Mixed: <ledger> — no reaction" (silent when hazardous — `HazardousMixReactor` owns that theatre), "Vessel full!" on overflow.
- **`StationStatusLabel`** — the station billboard shows live sim state: Heat "62 C -> 150 C" (+"Light the burner" when gated), Filter/Collect/Crystallise percentages.
- **Hover cards** (`HoverInspector` → `LabInfoDatabase`, right-hand ray): static what-is/how-to blurbs + a live "Now: 120 ml Ethanol / Mixed from: …" line. Suppressed on held items. `ProximityLabel` = the near-name tag; **`GlyphSafe.Sanitize` on EVERY new TMP string** (LiberationSans lacks ☑▶→Δ↑°).

## The playability battery (W5.40, 2026-09-02)
**`Tools ▸ PharmaSynth ▸ Simulate Everything (full playability check)`** — one command,
one report (`Logs/simulate-everything.txt`), one verdict. It answers "is every experiment
actually doable right now?" without a headset. Composed of, in order:

1. **All NINE modules** through `SimulatedRun.Run` — the real player path (pours drawn out
   of real bottles in verb-contract increments; completion only through the real event
   chain). Per-module transcripts stay at `Logs/simrun-<moduleId>.txt`.
2. **The campaign loop** (`SimulatedCampaign.Run`) — gate FSM, picker, quiz, grader,
   cutscenes, unlock chain → `Logs/simcampaign.txt`.
3. **Tutorial guidance coverage** — every step must resolve to an object to point at.
4. **Reachability** (`ReachabilityAudit`) — see below.
5. **Imperfect play** (`SimulatedMisplay`) — see below.

⚠ Every stage in it MUTATES the open scene; the report's own footer says to reopen
SampleScene afterwards. Vessel contents are snapshotted and restored, as in `SimulatedRun`.

**`tutorial-methane` is now simulated** (it was the only module nothing covered — the
campaign sim used to `RecordResult` it as passed purely to unlock Exp 2). Two new handlers
in `SimulatedRun`: `SimulateGrind` (circles the pestle, same shape as `SimulateStir`) and
`SimulateMethane`, which carries the burner/collection tube/match into position and puts
them back — the same "hold the dish to the flame" pattern `SimulateFlame` already used.

⛔ **Two edit-mode traps cost a full debugging pass here, and both generalise.** The rig
wires itself to `ExperimentStarted` from `OnEnable`, which does not fire in edit mode, so
**none of its five conditions registered** — the grind measured `progress 1.00,
IsGrindComplete=true` and the step still never completed, which reads exactly like a broken
verb. And `TemperatureSim.Update` (`→ Tick(deltaTime)`) does not run either, so a lit
burner held to the tube never warmed it: the rig only ever calls `SetHeating`. The sim now
calls the rig's public `HandleExperimentStarted` and ticks the temperature sims itself.
`MethaneApparatusRig.Update` was refactored to `Step(float dt)` (public, with an internal
`_clock` replacing `Time.time`) so the simulator drives the REAL frame, not a copy of it.

**`SimulatedMisplay`** — the player who gets it WRONG, which is the question that actually
decides whether the experiments are doable. Per module, on a freshly built stage each
time: pour the wrong reagent into a task vessel (must be flagged, and the binding must
still count the correct reagent afterwards), attempt an out-of-order step (must be refused
AND flagged), and drain a required reagent (`ReagentSupplyMonitor.EvaluateNow` must name
the task, and `RefillSourceBottles` must restock it — that call is the whole of Tutorial
Mode's no-dead-end guarantee). Plus the **restart matrix** (gameplay-flow §9) driven
through the real `GatekeeperModel`, walked legally from `Blocked` each time rather than
force-set, so the walk itself proves the path in.

**`ReachabilityAudit`** — the one thing the run sim structurally cannot see: a step can be
mechanically perfect while its bottle sits inside a closed cabinet or above head height.
The run sim reaches everything by reference. Input is the already-verified
`TutorialTargets` sweep. Two geometric checks, deliberately not a navmesh (the player has
continuous locomotion, so "can I stand near it" is almost always true): a height band
(0.05–2.1 m hard, 0.25–1.9 m comfortable) and an enclosure probe (six rays; blocked on
**every** side = walled in — one open side is an open shelf and must not be flagged).

⚠ **Probe hygiene is load-bearing.** The first `SimulatedMisplay` pass reported 11 bugs and
**every one was the harness, not the game**: the probes shared a run, so the wrong-reagent
probe delivered the step in full and the starvation probe then blamed the monitor for
correctly seeing no shortfall; the drain matched by asset REFERENCE while
`ReagentSupplyMath` keys availability by `chemicalName`; and recovery was asserted on TASK
completion when a task may name several reagents and the probe pours one. Each probe now
rebuilds the stage (`StartExperiment` rebuilds the graph but **not** the scene, and a
`LiquidTaskBinding` accumulator lives on the component). Findings are worth nothing if the
harness contaminates itself — confident nonsense is worse than no coverage.

**`TaskGraph.HasCondition(taskId)`** exists for exactly this: a verb whose condition never
registered is indistinguishable, from the outside, from a verb the player performed badly.
The simulator's failure messages print it.

## Tutorial Mode (2026-08-07)
Ungraded guided practice. Player-facing behaviour → `gameplay-flow.md` §14. This section is the mechanism.

**The flag.** `Progression/TutorialSession.cs` — one static bool, same shape as `DemoSession.Active`. Set by `MainMenuController.EnterLab(demo, tutorial)`, which always writes **both** flags so no entry can inherit a stale mode.

**The target resolver.** `Interaction/TaskTargetRegistry.cs` holds two things:
- `TaskTargetRegistry` — `taskId → List<TaskTarget>`, where `TaskTarget = { transform, TargetRole, stayLitWhenHeld, VerbKind }`. Roles: `Source` (amber, goes quiet in hand), `Destination`/`Tool` (green, stays lit while held), `Station`. **This is the renamed `ExperimentStationRegistry`**, which had been dead since the zone-free conversion (2026-07-17) removed every `ExperimentTaskStation` — nothing registered, so `WaypointGuide` called `Hide()` every frame in all 9 modules. Its `Clear()` was already wired into all 5 teardown points; that plumbing carried over unchanged.
- `TutorialTargets.Build()` — sweeps the live scene once per run and fills the registry. **Derived, never authored.** It reads the components that ACTUALLY complete each step, so guidance cannot drift from its binding — the exact bug class the W5.34 clueless-player audit was spent on. Sources: `LiquidTaskBinding.ExpectedSteps` (its own transform = pour destination, `step.reagent` matched against `LiquidPhysics.currentChemical` = source bottle; this also covers scoops, which complete via `AddLiquid`), the `TaskId` getters on `GrindController`/`StirController`/`VesselHeatTask`/`VesselChillTask`/`VesselLitmusTask`/`VesselFlameTask`/`VesselWeighTask`/`VaporCollectController`/`ZoneSimStation`/`RackTaskGroup`/`WeighStation`/`FermentationController`/`ExperimentTaskStation`, and `ExperimentTaskStation.RequiredItemId` → the matching `LabItem`.
  - ⚠ The zone-free verbs put the taskId on a **per-vessel companion** (`VesselHeatTask`, …), not on the apparatus controller — the bath/bucket/strip are shared bench tools and cannot know whose step is running. Sweep the companions.
  - ⚠ `ZoneItemSensor` is **not** a source: it is continuous-occupancy for rigs and carries no taskId at all.
  - ⛔ **A target must be VISIBLE (`TutorialTargets.Visible`, W5.42).** The sweep searches
    with `FindObjectsInactive.Include`, but some objects are switched off DELIBERATELY for
    the module being played — the module's own end product (`EndProductVisibility`), the
    methane-only staged props (`MethaneStageVisibility`), and the dispensers' hidden
    `Template_*` clone sources. Registering them made Tutorial Mode glow, ghost and aim a
    waypoint at something invisible. Safe by construction: the destination/station is
    registered BEFORE the source/tool lookup, so a dropped hidden object can never leave a
    step target-less. Suite-pinned.
  - **The VERB is derived in the same sweep (W5.39)**, so a demonstration can never mime a motion the binding will not accept: the `LiquidTaskBinding` branch reads `step.reagent.state` (Solid → `Scoop`, else `Pour`), `GrindController` → `Grind`, `StirController` → `Stir`, every other `RegisterVerb` → `Place`. `Place` is also the DEFAULT on `Register`, so pre-W5.39 callers (`MethaneApparatusRig`) keep working — and "carry it there" is the right guess for an unknown step.
  - ⚠ `tutorial-methane` stages no dynamic vessels and hard-codes its four task ids inside `MethaneApparatusRig`. The rig publishes `RegisterTutorialTargets()` **beside its RegisterConditions block** (so the ids can't drift) and `TutorialTargets.Build()` calls it — the rig does not self-register, keeping one registry lifetime.
- **Coverage check: `Tools ▸ PharmaSynth ▸ Audit Tutorial Targets`** → builds all 9 stages in edit mode and reports any step with no object, to `Logs/tutorial-target-audit.txt`. **Deliberately a menu item, not a suite pin**: it must `Build()` each stage, which mutates the open scene, and the suite stays side-effect-free. Run it after changing a module's tasks, layout, or verb wiring. Currently 9/9 modules, 81/81 steps resolve.

**The driver.** `Interaction/TutorialHighlighter.cs` on the runner object. Polls at 5 Hz, diffs the target set, touches only objects entering/leaving it. **It never decides a step is done** — pure read of `AvailableTasks()`; completion happens through the existing binding and the glow follows next poll, so no parallel detector exists to disagree. Glows **all** available tasks (parallel graph branches), suppresses everything while `TimeSkipController.IsSkipping`, and self-heals if the registry is empty mid-run.

**Channels.** `HoverHighlight` now carries **two independent flags** (`_hover`, `_guide`) with one `Apply()` — a single bool meant sweeping a ray past a guided object silently killed its glow. Guide tint wins over hover. `WaypointGuide` revived against the registry: one arrow only, **source first**, hopping to the destination once the source is held. Placement is anchored to `SolidWorldBounds`, **not the transform origin** — a shelf bottle's origin sits at its base, so "origin + up" buried the marker inside the bottle (headset capture, 2026-08-07). A short upward raycast detects a **shelf-caged** target (a plank directly overhead); caged markers are pulled OUT toward the player at mid height instead of upward, the same escape `ProximityLabel` makes for the same reason. **Distance-proportional size:** apparent size is size ÷ distance, so the marker grows LINEARLY with eye distance (`DistanceScale`, suite-pinned) to hold a constant angular size — a fixed-size beacon shrinks exactly as fast as the thing you cannot find, which is backwards. Clamped at BOTH ends on purpose: no floor and it vanishes when you lean over the bench, no ceiling and a marker across the lab fills the view. Knobs: `heightOffset` 0.16, `shelfClearance` 0.4, `frontDistance` 0.3, `markerScale` 3.2, `referenceDistance` 2 m, `minDistanceMul` 0.55, `maxDistanceMul` 3.5.

⛔ **Changing a `[SerializeField]`'s C# default does NOTHING to a scene that already saved it.** `heightOffset` sat at its original 0.55 long after the default became 0.16, so the placement fix silently did not apply. `Build Tutorial Scene Wiring` now pushes every tuned value through `SetPlacement`/`SetMarkerScale`. Related: `markerHomeScale` is SERIALIZED and captured once — deriving the base size from the marker's current scale would compound on every builder re-run (3.2 → 10.2 → 32.8). Pure `MarkerPosition` is suite-pinned; beacon renderers use `Art/Materials/TutorialBeacon.mat` (Unlit, `ZTest Always`, `ZWrite Off`, queue 4000) so it reads through a closed cabinet door — its own asset, never a shared bench material.

**Glow shell (`Art/Shaders/PharmaGlow.shader` → `PharmaSynth/GuideGlow`).** Tinting the object's own base colour was not enough — it read as "this bottle is orange now", not as a light. Each guided object gets a shell copy of its solid meshes carrying a TWO-PASS material: an additive **fresnel rim** (`ZTest LEqual`, `Blend One One`, `Offset -1,-1`) that is brightest at the silhouette and transparent through the middle, plus a flat **through-wall ghost** (`ZTest Greater`, `Blend SrcAlpha One`). The **pulse is computed from `_Time` in the shader**, not driven per-frame from C#: no Update loop, no framerate stutter. `_PulseMin` keeps it from ever blinking fully out, which reads as a fault. Two materials, one per role — `TutorialGlowSource` (amber, "fetch this") and `TutorialGlowTarget` (green, "put it here"). Knobs, retuned against a headset capture (user 2026-08-07 — the first pass was a fast, tight, dim shimmer that read as a specular highlight rather than a marker): `_Intensity` 4.5 (brightness) · `_RimPower` **1.1** (LOWER = wider halo) · `_PulseSpeed` 1.3 (~5 s a breath) · `_PulseMin` 0.15 (deeper swing) · `_Occluded` 0.5 · **`_Swell` 0.012** — the shell also breathes OUTWARD along the normal, in **metres of world space**, so the pulse changes SIZE and not only intensity, and a test tube swells as visibly as a Florence flask instead of by a fraction of its own scale.

⛔ **URP draws ONE pass per matching shader tag.** Both passes were first tagged `"LightMode"="SRPDefaultUnlit"`, so only the rim ever drew and the through-wall ghost silently never did — verified by DevCapture, invisible to every compile and suite check. The forward renderer matches `SRPDefaultUnlit`, `UniversalForward` and `UniversalForwardOnly`, so **each pass needs its own tag**. Any future multi-pass overlay hits this.

⚠ A ghost renderer needs **one material per SUBMESH** (`sharedMaterials`, length = `subMeshCount`) — a single material draws only submesh 0, so a two-part prop (bottle + cap) glows in half.

**X-ray silhouette.** `TutorialHighlighter.AddXray` parents a child carrying a COPY of the target's solid meshes, drawn with `Art/Materials/TutorialXray.mat` (ZTest **Greater**) — so the ghost appears only where the object is occluded and an unobstructed bottle looks completely normal. Applied to `Source`/`Tool` roles only (the "go find it" ones); destinations are already the glassware in front of you. Filtered by **`ExperimentSceneBuilder.IsSolidMesh`** — the shared "is this part of the body?" predicate that `SolidWorldBounds` also uses, so the two cannot drift.

⛔ **Two bugs made the first ghosts hugely oversized, and both are easy to repeat.** (1) It rolled its own filter and kept only `IsEffectChild`, missing the **`TMP_Text`** clause — so each item's floating `ProximityLabel` was silhouetted, and that label carries a large compensating scale to undo its parent's. (2) Ghosts were parented under one root with `localScale = mf.lossyScale`, feeding a **WORLD** scale into a **LOCAL** field beneath an already-scaled parent, applying the target's scale twice. Now each ghost is parented to the mesh it copies with **identity local TRS** — exact match, follows the object for free, no arithmetic to get wrong. Not a URP Renderer Feature — that needs a dedicated layer, and layers are load-bearing for XRI interaction masks.

⛔ **`Art/Shaders/PharmaGuide.shader` exists because URP's stock Unlit does NOT declare a `_ZTest` property** — `material.SetInt("_ZTest", …)` against it is a **silent no-op**: the material inspects as configured, serializes without the property, and renders with ordinary depth testing. Both guidance materials looked right and would have shown through nothing. Use `PharmaSynth/GuideOverlay` (declares `_ZTest`) for any see-through overlay; verify by grepping the `.mat` for `_ZTest`.

**Support.** `WristWatchController.StepText` prints the task `hint` under the label (and drops Mastery, a graded number). `ProximityLabel` — radius × **2.5** (not the 4× first drafted: the reagent cabinets alone hold 57 bottles, and 5.6 m lights the whole east wall into text soup), plus `ShouldShow` labels a **guided** object at ANY distance, which is the one label the player is hunting for. `DemoHudController.SkipAllowed` reuses the existing Skip button (Finish/Auto-Quiz stay demo-only). `UI/TutorialCoach.cs` = the stuck ladder (`LevelFor`: 15 s / 30 s / 60 s, resets on progress, speaks the step's EXISTING hint — no new voice lines) plus `SummaryText` (counts, never a percentage). `HoverInspector` already answered "what is this?" from `LabInfoDatabase` in every mode — nothing was added for it.

**Spotlight (2026-08-07).** `HoverHighlight` carries a THIRD channel, `SetDimmed`, driven by `TutorialHighlighter.ApplySpotlight`: while a step is guided, every OTHER grabbable is pushed 62% toward near-black. Glowing one bottle among 57 near-identical ones is only a RELATIVE signal competing with 56 equally bright neighbours — dimming the rest makes it absolute, and it is the single biggest findability win in the mode. Priority is **guide > hover > dim > untouched**, so a dimmed object you deliberately point at still responds. The `HoverHighlight[]` sweep is cached per RUN (~79 objects), and `SetDimmed` early-returns when unchanged, so a minute-long step costs one pass rather than one per poll. The spotlight only engages while something is actually guided — dimming the lab during a target-less wrap-up step would read as the lights failing.

**Semantic haptics (2026-08-07).** `Interaction/LabHaptics.cs`. The VR affordance pass already buzzes every grab/poke, so picking up the RIGHT bottle felt identical to the wrong one, and in VR the score bar and toast are both easy to miss while looking at your hands. Two deliberately distinct SHAPES, not a rhythm — a short light tick on task-complete (0.45 / 0.06 s) and a long strong buzz on a mistake (0.85 / 0.22 s) — told apart instantly and neither needing a coroutine. Fired from the same two places the audio already fires, so there is one site per event.

**Reduce-flashing (accessibility, 2026-08-07).** `ComfortSettings.reduceFlashing` → `ComfortApplier` → `Shader.SetGlobalFloat("_GuideSteady", …)`. A GLOBAL, never a material write: the two guide materials are shared ASSETS, so setting `_PulseMin` on them at runtime would dirty them on disk in the editor and persist into the next session. ⛔ Named "_GuideSteady" and not "_GuideFlash" because an **unset shader global reads ZERO** — the default must therefore mean normal pulsing, or every scene that never touched the setting would come up frozen. When on, the wave is forced to its PEAK rather than its mean, so accessibility never costs the player brightness.

**Session-only progress.** `TutorialSession.BeginSession/MarkPractised/HasPractised` — an in-memory `HashSet`, never persisted, cleared every time the mode is entered so a second student at the same headset inherits nothing. `GatekeeperModel.ModuleOptions` shows "✓ practised" in place of campaign's "✓ PASSED": practice grades nothing, so claiming PASSED would be a lie.

**Practice ending.** `GradeScreenController.ShowPractice(steps, corrections, onDone)` reuses the campaign grade panel with **no percentage** — a score would turn practice back into an exam. No pass/fail visuals (nothing was judged), no Retry, no "Choose Another"; only Continue, which runs the caller's `onDone` and **short-circuits `onContinue`** so the campaign's unlock/advance chain can never fire from an ungraded run. Falls back to the old floating-text announce when no panel is wired (bare test scenes). Replaces announce-and-teleport-in-the-same-breath, where the summary was gone before it could be read.

**Orientation.** `PharmeeLines.TutorialOrientation`, spoken once after the ordinary greeting when the mode is active. A single fixed `const`, not a pool — it is an instruction, and a first-timer should hear the same words every time. ⚠ Any new spoken line must ALSO be added to `VoiceCorpus` or the suite fails (`voice: every PharmeeLines pool reaches VoiceCorpus`) — that pin caught this one immediately.

**Navigation & aiming cues (W5.44).** ⭐ **The design rule is that every cue is
CONDITIONAL** — Tutorial Mode already spends most of the player's attention, so a new
channel that is always on makes the existing ones weaker. Each cue below states when it
appears; *that* is the part a future session will break if it is not written down.

| Cue | Appears when | Never |
|---|---|---|
| **Ground path** (`GuidePath` + pure `GuidePathMath`) — chevrons flowing along the floor | a route exists AND the target is > 2 m away | while the beacon shows |
| **Beacon** (`WaypointGuide`) | within 2 m, or when no route exists (target inside a cabinet) | while the path shows |
| **Wrong-object nudge** | you pick up something the guided step does not want | outside a guided step; and it NEVER records a mistake |
| **Need line** (`VesselStatusMath.NeedLine`) | on the guided destination, until the amount is met | once satisfied — a "40 / 40" label invites an overpour |
| **Audio ping** (`AudioService.TryPlayAt`) | once, on a step change | never on a loop |

⛔ **The path routes on a NAVMESH, not in a straight line.** The benches sit in the middle
of the room, so a straight line to a wall shelf points through solid furniture — an arrow
that lies about the way there is worse than no arrow. `NavMesh.CalculatePath` needs no
agent, only a baked surface: **`Tools ▸ PharmaSynth ▸ Build Lab NavMesh`**. When no route
exists the path draws nothing and the beacon takes over — a fallback, not a failure.

⚠ **Known gap: bench-top navmesh islands.** `Build Lab NavMesh` collects render meshes for
the whole scene, so flat bench tops bake as walkable surfaces that are NOT connected to the
floor. When a step's target sits on one, `NavMesh.SamplePosition` snaps the goal to that
island — both ends report on-mesh, and `CalculatePath` still finds no route. Verified on
**midterm-acetone** (`Eq_Beaker_100mL` at y = 1.3, `startOnMesh=True goalOnMesh=True`, no
path); the other 8 modules route fine. It degrades exactly as designed — the beacon takes
over — so it is a quality gap, not a break. Fix when convenient: mark furniture
Not Walkable with `NavMeshModifier`, or bake the floor only. ⛔ Widening the goal search
radius 3 → 5 m was tried and changed nothing; the radius is not the cause.

⚠ **The NavMesh bake goes STALE when furniture moves**, exactly like the lightmap bake —
the benches ARE the obstacles it routes around. Re-run it in the same breath as
`Build Lab Probes` → `Run Lab Lighting Bake`.

Both navigation cues pick their target through **`TaskTargetRegistry.PickTarget`** (source
first, hopping to the destination once the source is in hand), extracted from
`WaypointGuide` so the path and the beacon cannot point at different objects — two cues
disagreeing about where to go is worse than either alone.

The wrong-object nudge rides the `TutorialHighlighter` poll that the spotlight already pays
for (~79 cached `HoverHighlight`s at 5 Hz), so it added no new sweep. It is **prevention,
not punishment**: the player is holding a bottle, not pouring it, and nothing is scored.

**Nothing dead-ends (W5.39).** Three states in the lab are irreversible; practice waives exactly the one that is. (1) `ReagentSupplyMonitor.Update` refills **before** `EvaluateNow()` in tutorial and returns — deliberately not folded into the demo branch below it, which is REACTIVE (it refills only once a step has already starved, so a bottle spilled early would sit empty for the rest of the run). The poll already sweeps every `LiquidPhysics`, so the refill is free. `SupplyPrompt` is therefore structurally unreachable in practice, not merely unlikely. (2) `OverheatEffects.RuinNearestVessel` early-returns — the smoke, hiss, alarm and recorded mistake all still fire, only the Ruined-Mixture conversion is skipped. (3) Nothing needed for breakage or consumables: a broken vessel goes home with its home contents while its `LiquidTaskBinding` accumulator survives (`GoHome()` teleports, it does not destroy), and the four consumable boxes have always been endless (`ConsumableDispenser`) — matches included, so a burnt-out match is never the last one.

**Verb demonstration (W5.39).** `Interaction/VerbDemoMath.cs` (pure) + `VerbDemoPlayer.cs` (thin). ⭐ **Deliberately not a hand**: rigging and animating hands is days of art for a hint, and it answers a question the player never asked. Ghosting the OBJECT says which thing moves, from where, to where, and how it is held at the end. `VerbDemoPlayer.Show(taskId)` reads the registry (Source/Tool = mover, Destination/Station = target — a source-less verb like stir or heat degenerates to a motion in place, which is correct), copies the mover's solid meshes and drives them along `VerbDemoMath.Sample` for 3 s × 2, then destroys them. Curves: `Pour` carries over then tips **past** horizontal (115° — stopping at 90° reads as hesitation) and levels off; `Scoop` dips, lifts, carries, tips; `Stir`/`Grind` circle at the vessel for the controller's **own** `OrbitMath.requiredRevs` (a demo of a shorter motion than the step accepts teaches the player to give up early); `Place` is an arc that never dips below either endpoint.
